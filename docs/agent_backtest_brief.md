# Agent 回测系统 — 开发任务书（Agent 启动提示词）

> 本文件是启动提示词本体。请完整阅读后开始工作。
> **维护规则：你（负责开发的新 Agent）在开发过程中发现的任何新盲区/误区，必须补写进本文件的【待补盲区】章节，并在提交说明中注明。本文件是你与人类共同维护的"风险清单"。**

---

## 一、使命

把 AI Berkshire 的 **Agent 驱动投资决策** 改造成 **可回测、可量化的决策系统**。

现状：系统由 LLM Agent 做研究判断（四视角研判 → 击球区 → 六道闸门 → 买入），决策路径是黑箱，无法回答"这个系统在历史上会亏钱还是赚钱"。

目标：构建回测框架，让 Agent 的决策逻辑在历史时点可复现、可统计验证。

## 二、你不需要做什么

- 不需要动现有生产系统（agent_driver/price_monitor/futu_bridge 等，别改）
- 不需要开发实盘/模拟盘交易功能
- 只做回测域：数据准备、决策复现、统计评估

## 三、三条技术路线（按顺序实施）

### 路线 B：决策规则回测（先做，第一阶段交付）
把 Agent 的决策逻辑从 `reports/` 下 **245 份四视角报告** 中**蒸馏成可复现规则**：
- 例：`ROE≥15 且 PE<历史30分位 且 股息≥3% 且 四视角无🔴 → 进入击球区；击球区 = 建仓价±N%`
- 蒸馏方法：读报告样本 → 提取"什么量化条件 → 什么结论"的映射 → 规则引擎实现
- 用规则做大规模历史回测：全 A 数千股票 × 近 5 年 × 日频，纯 Python 计算

### 路线 A：Agent 盲测（第二阶段，抽查用）
历史时点让真实 Agent 重新决策，做**行为学验证**（不是统计）：
- 抽 20 个左右历史时点，遮住公司名，只喂 ≤t 的信息，观察 Agent 决策与规则回测是否一致
- 目的：验证"蒸馏规则能代表 Agent"，不一致则修正规则

### 路线 C：交叉验证（第三阶段）
B 的统计 + A 的抽查 → 形成最终结论。

**先做 B。跑通后再做 A。不要倒着来。**

## 四、已知盲区与误区（硬约束，逐条落实到代码与数据）

以下每条都是**前视偏差（look-ahead bias）**的来源，回测系统的每一处设计都必须对照检查：

### 数据层面
1. **公司名泄漏（结果泄漏）**：LLM 训练数据里有公司后续走势。历史盲测时必须匿名化公司名。
   - 注意：**匿名化可能无效**——LLM 能从特征反推身份（"毛利率91%、ROE30%、高端白酒"=茅台）。必须连同可识别特征一起模糊，但保留行业上下文（决策需要行业判断）。平衡点：给出行业，声明"该行业有多家可比公司，不要假设任何具体公司"。
2. **信息集截断（新闻时间戳）**：决策时点 t 的 Agent 只能看到 ≤t 的信息。所有新闻/公告/研报必须打时间戳，投喂时严格过滤 `timestamp ≤ t`。
3. **幸存者偏差**：回测 2020 年的池子，必须是"2020 时点全市场可交易集合"，不是现在筛出来的 245 只。需要**时点截面（point-in-time universe）**：模拟每个历史时点时重建当时存在的股票全集（含后来退市/ST 的）。
4. **财报 PIT 时点**：财报数据的"实际可得时间"≠"报告期"。2025 年报的数字 2026-04 才披露。模拟 2026-01 决策时，只能用 2025 三季报及之前的数据。**必须按披露日组织财务数据**。
5. **指标重述**：公司爆雷后会重述历史财报。免费数据源通常是"修订后"数据，当时市场看到的是"首发版"。使用历史财务数据时需注意此偏差（免费源无法完全解决，需在报告中声明局限）。

### 模型与框架层面
6. **参数前视（最危险）**：现有阈值（-20% 止损、12% 仓位上限、六闸门容忍度、建仓价 15% 漂移阈值）是 2026 年定的。**回测中参数必须冻结为先验值，禁止"调到最优"**——回测只能验证参数，不能优化参数。任何"我调了一下参数结果更好了"都是自欺。
7. **LLM 知识边界**：即使匿名+截断，LLM 本身知道训练截止后的世界。缓解手段：角色锚定提示词（"你是 2022-10 的分析师，之后的任何事你都不知道"）。此偏差**无法完全消除**，属于 LLM 回测的先天残差，需在最终报告中量化声明。
8. **框架后见之明**：现有六闸门/反锚定等框架是 2026 年设计的，带着设计者看过 2026 年市场后的后见之明。无法消除，只能声明局限。

### 成交与组合层面
9. **成交可行性**：涨停买不进、跌停卖不出、停牌不可交易。规则回测必须模拟这些约束（可用涨跌停价格数据判断）。
10. **组合路径依赖**：资金曲线必须按时间顺序逐日推进模拟（先卖后买、资金复用），禁止"批量独立计算每只股票收益再求和"。

## 六、开发约束

1. **算力预算**：批量四视角研判和定时任务是生产系统的开销。回测开发应尽量用规则引擎（纯计算），Agent 调用只用于第二阶段的少量盲测（20 个时点以内）。**禁止大规模批量调用 LLM 跑历史时点**。
2. **数据源优先级**：免费优先（AkShare/baostock/东财/新浪历史），PIT 财报数据若免费源无法满足，降级为"按季度批量时点"处理并在报告声明。
3. **可复现性**：回测要有固定随机种子（如有随机）、完整数据快照记录、结果可重跑。
4. **不污染生产**：回测脚本放独立目录（如 `backtest/`），不动 `tools/` 和 `data/monitor/`。

## 七、第一阶段交付物（路线 B）

1. `backtest/` 目录 + README（设计文档：蒸馏规则清单、数据 schema、回测引擎架构）
2. 蒸馏规则文档：从 245 份报告中提取的"条件→结论"映射表（每条规则注明来源报告样例数）
3. PIT 数据集构建脚本：时点截面 + 按披露日的财务数据（至少覆盖 2021-2025）
4. 回测引擎：逐日组合模拟（含涨跌停/停牌约束、仓位、止损规则）
5. 第一份回测报告：策略 vs 基准（沪深300/全A等权）的收益/回撤/夏普/胜率，含参数敏感性分析（**只展示敏感性，不改参数**）
6. 盲区清单更新：把开发中发现的新盲区补进【待补盲区】

## 八、验收标准

- 回测结果可一键重跑，任何人运行同一代码得到同一结果
- 每一处"用什么数据、什么时点"的选择都有注释说明为何无前视
- 报告明确区分"验证结论"与"声明局限"
- 蒸馏规则与报告结论的一致性抽查通过（抽 10 份报告人工比对规则输出 vs 报告结论）
