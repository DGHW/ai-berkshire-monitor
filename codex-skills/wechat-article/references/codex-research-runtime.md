# Codex 研究执行契约

适用于本项目 Codex skills 的研究执行。它替代源正文中 Claude/WorkBuddy 的工具名、权限检查、限流合成与执行时限；具体上下文边界、首轮顺序、领域判断和终审责任也以本契约为准。财务纪律、evidence-only的估值边界和冻结的交易判据仍沿用原项目。研究授权不等于交易授权。

## 真实派发与容量

- 源中的 `Task` / `Agent` 意味着实际调用当前运行时的 `spawn_agent`，不是由 lead 写几段角色口吻。无需 `TeamCreate`、`TaskCreate` 或 `TeamDelete`。使用实际暴露的 API 参数，不臆造工具。
- 独立研究使用通用研究 Agent，模型默认继承当前模型，不把代码探索角色误用于公司研究，不因限流静默换弱模型。
- 如支持 `fork_turns`，每位新研究员显式设 `fork_turns="none"`，以任务书传递上下文。若运行时只能继承历史，披露这一限制；内容隔离不能宣称为物理上下文隔离。
- 并发数服从当前会话容量，包含 lead 时须给 lead 留一个位置。本会话若总容量是 4，四大师按 3+1 波次完成，随后 Bull/Bear 两位；分批派发不减少角色数。Agent 不能自行再开团队以绕过容量或成本限制。
- `investment-team` 要 4 位实际研究员；v2 standalone / evidence-only 与 super full 要 4 位分析师 + Bull + Bear 共 6 位实际研究员，lead 负责协调与终审。super lite 明确用 2 位合并维度分析师（商业+行业、财务+治理风险）+ Bull/Bear，共 4 位，不宣称完成四大师独立研究。`investment-team-lite` 仍沿用单 Agent 速评，不包装成团队。
- 其他技能按原任务所需角色真实派发，遇容量限制分波。已授权研究无需再等框架展示确认。source 的预估分钟数仅作估计；停止条件是关键问题获得证据或明确记录无法取得，不是把计时器跑完。

## 派工前的两包与行业卡片

lead 先确认标的、研究模式、用户限制、客户端研究日期及数据截止时间、实际仓库/解释器、输出目录。检查本会话真实可用的网络与数据工具；缺少 `.claude/settings.local.json` 不表示 Codex 无网。工具失败必须写明，禁止用训练记忆冒充最新披露。

运行 `tools/industry_valuation.py lookup --code CODE`，将行业卡片或无映射情况写入任务。★★★★+ 禁止 PE 直算，检查卡片要求的隐藏资产负债表和适用方法。未知行业由分析师先判断并报告；Codex 研究不自动修改共享行业映射。

给研究员两个分开的包，每条事实保留 period / basis / scope / unit / source_tier / source / filing_date / confidence：

1. Canonical Anchor Pack：T0/T1 财务披露与结构化事实；价格、股数、币种和每股/ADR 口径单独标注。未核实写缺失或待核实，不把 lead 的猜测伪装成锚点。
2. Research Context Pack：新闻、共识、管理层表述、竞品事件、市场叙事，只作为待检验的线索。T2 provisional 不进入 Base Case 核心 driver，T3 不覆盖财务事实。

分析师能纠错锚点，须引用原始依据回报。正式采纳纠错后，把更新后的事实发给受影响研究员；不发送“请对齐 lead 的结论”。

## 每位 Agent 的上下文

每份任务书只给标的、角色问题、两包、行业卡片、必要来源/工具、可读文件和唯一可写文件的绝对路径、验收输出。不要把整份 super skill、lead 既有结论或全部聊天历史塞给每位分析师。所有人共享文件系统：明确文件所有权，告知“你不是独自在代码库，不还原他人修改”。

任务书可以直接采用以下骨架，再填该角色具体研究问题：

```text
标的/模式/研究日/截止日：...
角色及必须回答的问题：...
Canonical Anchor Pack：...（或绝对路径）
Research Context Pack：...（或绝对路径）
行业卡片、数据纪律、可用工具：...
可读文件/本轮不能读的报告：...
你唯一拥有的输出文件绝对路径：...
你不是独自在代码库，不还原他人修改。不要自行再派 Agent。
交付明确领域判断、证据、反证、尚未解决的问题、改判条件及完成状态。
```

源正文所指 `references/red-team.md` 等文件若不存在，先检查同一源正文后半部的内嵌规格（本仓库已将红队及路由规格内嵌）；使用实际存在的模板，禁止卡在虚构路径或假称已经读过。

| 角色 | 第一轮可见输入 | 应回答的判断 | 第一轮不可见 |
|---|---|---|---|
| business（段永平） | 两包、商业问题、行业卡片 | 钱为何重复流入；护城河在变强还是变弱；最强反证 | 其他分析师报告、Bull/Bear 立论、旧目标价、旧终审 |
| financial（巴菲特） | 两包、财务问题、行业卡片、确定性算术工具 | 利润能否转成所有者现金；哪项正常化假设最危险 | 其他角色结论、旧建仓价、预填估值结果 |
| industry（芒格） | 两包、竞品/产业链问题、行业卡片 | 谁能获得新增利润；最强替代品和竞争破坏路径 | 其他角色报告、lead 的赛道评级 |
| risk（李录） | 两包、治理/风险问题、行业卡片 | 哪条风险足以破坏论文；发生机制、证据、监测信号 | 其他角色结论、旧终审和仓位 |
| Bull | 完成的四份报告、事实纠错、两包、明确模式 | 最值得下注的一条因果链与最弱环节；FOR 立论 | 第一轮 Bear 立论、预填裁判结论 |
| Bear | 与 Bull 相同的研究输入、冷信息/治理核查任务 | 最强 AGAINST 立论；利空是事实、概率还是已被计价 | 第一轮 Bull 立论、预填裁判结论 |
| lead / judge | 全部已完成研究、两轮辩论、S3 模型及局限 | 哪一方赢在什么证据；此价格下采取什么行动 | 不使用尚未返回的结果 |

证据阶段保留“领域判断”：例如现金转换不可信、护城河收窄、治理可接受，不能为了删除买卖结论而只剩资料摘抄。判断须附因果机制、证据与反证。v2 evidence-only 不产目标价、总回报、仓位或最终买卖建议；财务角色在此模式只给模型输入与关键假设。

在 evidence-only 的分析师任务书中不主动预填当前价格、旧价格带或价格隐含预期；价格留给 S3。风险/行业仍可研究事件与市场叙事，不按股价反推生意好坏。standalone 的财务估值可在商业证据形成后取得必要价格输入。旧报告可在独立研究完成后用于增量比较，遵守生产反锚定冻结规则，不把旧结论先写进任务书。

## 一轮盲立论、一次实际互驳

1. 四位分析师各自完成并落盘，lead 处理事实口径冲突；原始领域判断保留。
2. Bull/Bear 用新的独立上下文并行第一轮立论，保留 FOR / AGAINST 角色。每人还须检查自己立论最薄弱的一环；Bear 空手而归合法，但交付查了什么、查不到什么和为何未命中。
3. 收齐双方第一轮后，lead 给两人对手的完整已完成立论和待裁决问题。运行时有 `followup_task` 时，用它续跑同一个 Agent；`send_message` 仅给正在运行的 Agent 补材料，不用于唤醒 idle Agent。若 API 名不同，使用其实际能启动新一轮的能力。
4. 第二轮逐条标【坚持】/【让步】/【未知】，回应对手具体证据；记录新增证据和修正的假设。未返回第二轮不得写“辩论完成”。收敛即停，尚影响决策的实质争议交给已有角色做窄范围核查。

S2 可并入分析师/Bear 任务书并复用已有证据，但“涉及了该主题”不是“完成核查”。每个命中专项记录具体问题、负责 Agent、查过的来源、发现/缺口；关键问题未覆盖就追加该角色的窄任务，不重复开整套技能团队。

## 验收：文件数不是 Agent 数

在本次输出目录保存 `agent-runs.json`，记录 skill/mode、实际 runtime、每次 spawn 返回的 ID、角色、上下文方式、轮次、状态、产物路径，以及限流/失败/缺失。ID 与完成状态来自实际工具回执，禁止预填。记录是可追溯清单，不是独立于执行日志的真实性证明。

研究员产物最少含：

- 明确领域判断或角色立场、2-3 条关键因果论点及直接来源/页码或可定位原文。
- 事实、推断、假设分别标注；收益敏感的数字有时点、口径和算术记录。
- 最强反证、尚未解决的分歧、哪项证据会使自己改判；无新增发现也应如实说明。
- 完成状态与数据/网络缺口。完成不能仅由五字段可解析、字数够、文件时间够新判定。

限流先减并发/分波，修复后继续缺失角色。无法继续时报告 incomplete 与缺失角色；用户明确选择单 lead 才可交付 lead-only，并说明独立研究缺失。不得用旧文件、统一结论的补写或一份综合报告拆四份来补足真实团队验收。格式修复与数据纠错可以做，不能抹掉有证据的分歧。

## 终审必须留下一个真实决策

super S5 和 v2 standalone 都须明确：**现价买入 / 等待具体价格或事件 / 回避**；已有持仓另给持有/减仓/退出判断。等待是合法判断，但必须写触发条件和等待的机会成本。证据不足则明确“当前不可定价/不行动，缺 X”，不得为强制站队捏造点估值、概率或收益数字。

最终回答：

1. 我的主张，以及最值得下注/最应回避的那条业务因果链。
2. 市场或对手可能错在哪里；若不存在可证实的预期差，明确说没有发现。
3. Bull/Bear 哪条最强论据胜出，另一方为何未改变当前行动；保留仍有影响的分歧。
4. 主期限及可计算的情景回报/下行，引用 S3 已完成模型，不重新建模；primary horizon 先定后算。
5. 哪个假设最易错、可观察的证伪阈值和日期、转向的价格/事件。
6. 空仓与持仓者的具体行动；未知用户仓位时用条件建议，不假设仓库上游持仓是用户资产。

没有证据的强硬用词不算锋利。锋利性来自可验证的下注、反方检验、机会成本和会让自己改变主意的条件。

S3A 的价格隐含假设用于审计，不能作为加减项再次修正 S3B/S3C 的基本面价值（防 double count）。S5 选择有证据支持的争议假设并引用对应模型结果；如假设尚未计算，回到原 S3 计算，禁止裁判心算一个新目标价。

交互研究输出到当前任务获授权的目录。不要调用 `agent_driver review/run-one`、生产补写/归一或 `report_sync --sync-pool` 验证 skill：它们可能更新池或触发交易。本契约不修改六闸门、凯利、反锚定或无人值守生产流程。
